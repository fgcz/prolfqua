# Statistical standards compliance: prolfqua 1.9.4

Assessment date: 2026-11-16. The selected category is **Regression and Supervised Learning** (`regression`), alongside the mandatory General standards. The package fits regressions to proteomics features, computes contrasts and uncertainty, and adjusts for multiple testing. This assessment follows the requested `stats-standards-compliance` skill and the approved srr groundwork plan. No other category was requested or scored in this pass.

The canonical [checklist](srr-standards.md) contains 68 General and 48 Regression standards, downloaded through srr 1.1.0.9000 against standards version 0.3.0. Full source texts are [General](general.html) and [Regression](regression.html), obtained from the [rOpenSci review book](https://github.com/ropensci/statistical-software-review-book/tree/main/standards). All 116 IDs were assessed individually; the [assessment TSV](standards-assessment.tsv) records current status, potential verdict, evidence, gaps and tag location.

## Current implementation and potential feasibility

Current **met** means implemented and supported by the inspected code, documentation and tests. **Partial** retains an explicit limitation and is not counted as fully met. **Not met** stays `@srrstatsTODO`. **NA** has an explicit reason in the central `NA_standards` block. As specified by the approved plan, partial evidence receives an `@srrstats` annotation only when the text states its limit. Consequently the srr tool counts more annotations as compliant than this assessment counts as fully met.

The skill uses a different, prospective verdict: **Y** includes both implemented requirements and unfinished work achievable within the current architecture; **N** means a fundamental scope conflict; **NA** is outside the present workflow. Potential scores are always **Y / (Y + N + NA)**, including NA in the denominator. A potential Y does not mean the feature exists, the work is small, or submission is ready.

Implemented evidence includes validated formulas, categorical predictor/loss-of-information documentation, and a rendered [formula-to-design article](../vignettes/articles/LowLevelAPI.html) with asserted one-factor and interaction contrasts (RE1.0–RE1.3a). Strategies expose model specifications before fitting (RE4.1); Model, ModelLimma and ModelFirth retain fitted results (RE4.0), and their explicit coefficient accessors satisfy RE4.2. The standards explicitly allow equivalent accessors, so lack of an S3 generic alone is not treated as failure. Main facades retain `$.lfqdata` for response/design access (RE4.8); standalone matrix-model objects retain less metadata, a limit stated in the annotation.

The [runtime data](runtime.tsv), [reproduction script](benchmark-runtime.R) and [environment](runtime-session.txt) support RE5.0. With 12 samples and three peptides per protein for nested models, facade-construction timings for 500/1000/2000 proteins were 0.173/0.288/0.592 s for lm, 0.077/0.043/0.050 s for limma and 7.902/15.314/29.667 s for lmer_nested. These are single illustrative runs with fixed design and no missing responses; lazy contrast extraction is excluded, and some mixed-model fits emitted convergence warnings. No universal runtime guarantee or inference-quality claim follows from them.

Feasible work still unfinished includes explicit NA/NaN/Inf and missing-predictor policies, preprocessing diagnostics for dependence, uniform per-protein convergence metadata and controls, coefficient intervals and uniform formula/nobs/covariance/fitted/residual access, transformation provenance, useful object print/summary/default plotting, fitted-response intervals, and broader backend/reference/recovery tests. Much information already exists in inner fits, but matrix and detection backends need consistent semantics before adding public accessors.

Regression NA reasons: **RE4.14** forecast-error aggregation, **RE4.15** forecast-error access, **RE4.16** extrapolation diagnostics, **RE6.3** forecast plots and **RE7.4** forecast/extrapolation tests do not apply because prolfqua offers designed-experiment contrast inference and no public prediction or forecasting workflow. Adding such a workflow would require reassessing those NA declarations. No entire Regression subsection is NA.

## Scope and category recommendation

Potential scope is viable for both General (65/68 = 95.6%) and Regression (43/48 = 89.6%), exceeding the skill’s 50% feasibility threshold in each set. All missing applicable work can plausibly fit the current data/strategy/model/facade architecture. After reviewing input structures, covariance extensibility, model accessors, convergence and statistical tests, no applicable requirement warranted N: missing implementations are engineering gaps, not incompatible inferential frameworks. This does not imply those gaps are trivial.

**Recommend Regression and Supervised Learning.** Its model, contrast, uncertainty and designed-experiment workflow matches the package directly. Other categories were not assessed here, so this report neither ranks them nor claims a viable secondary category. Current fully implemented shares remain below 50%; the feasibility result and 88 annotated claims are not a declaration that review submission is ready. The [srr pre-submit output](pre-submit.txt) and [generated srr report](srr-report.html) retain the intentional TODOs.
